# Fake user generator

A web page that generates fake users for Uzbekistan (`uz_UZ`) and Kazakhstan (`kk_KZ`): name, address,
coordinates, height, weight, eye and hair color, phone and email. All data is generated by SQL functions in
PostgreSQL. The Flask app reads the country list, calls `generate_users` and shows the rows.

## How to run

```sh
createdb fake_users
psql -d fake_users -f sql/install.sql
pip install -r requirements.txt
DATABASE_URL=postgresql://localhost/fake_users flask --app app run
```

`install.sql` runs `01_schema.sql`, `02_data.sql` and `03_functions.sql` in one transaction and then
`04_tests.sql`, which prints a table of checks (every `ok` must be `t`). It can be run again, existing rows
are skipped. On macOS port 5000 is taken by AirPlay Receiver, so add `--port 5001`. On a server run
`gunicorn app:app` with `DATABASE_URL` set.

The page has three URL parameters: `locale`, `seed` and `page` (batch number from 0), for example
`/?locale=kk_KZ&seed=42&page=3`. A new country or seed starts from page 0, Next and Previous change only `page`.

## Database

All lookup values are in one table `names(locale, kind, idx, value)`. `kind` says what the value is, `idx` is
the number of the value inside `(locale, kind)`, from 0 to n - 1 without gaps. The primary key is
`(locale, kind, idx)`, so reading value number `i` is one index lookup. `dict_size(locale, kind, n)` stores n,
so the functions never run `count(*)`.

| kind | uz_UZ | kk_KZ | example |
|---|---|---|---|
| `first_male`, `first_female` | 605, 560 | 3479, 1389 | Aziz, Malika |
| `last_male`, `last_female` | 135, 135 | 156, 156 | Karimov, Karimova |
| `title_male`, `title_female` | 1, 1 | 1, 1 | Mr., Ms. |
| `patronymic_male`, `patronymic_female` | 1, 1 | 1, 1 | o'g'li, qizi / uly, qyzy |
| `city`, `street` | 40, 50 | 40, 50 | Tashkent, Amir Temur |
| `street_word`, `house_word`, `apartment_word` | 1, 1, 1 | 1, 1, 1 | ko'chasi, uy, xonadon / koshesi, ui, pater |
| `hair_color`, `eye_color` | 8, 7 | 8, 7 | Dark brown, Hazel |
| `phone_country`, `phone_operator` | 1, 13 | 1, 8 | 998, 90 / 7, 701 |
| `phone_format` | 4 | 4 | `+%1$s (%2$s) ### ## ##` |
| `email_domain` | 5 | 5 | gmail.com, umail.uz |
| `country` | 1 | 1 | Uzbekistan (shown in the country list) |

To add a locale, insert its rows into `names` for every kind above (`idx` from 0) and run
`psql -d fake_users -f sql/02_data.sql` again: its last statement updates `dict_size`. The functions and the app
do not change, and the new country appears in the list.

## Functions

Every random value gets its own text key `locale:seed:batch:position:field`, for example `uz_UZ:42:0:3:city`.
`rnd_key` builds the first four parts, and each function adds a field name. The same key always gives the
same number, and different fields get different keys, so they do not depend on each other.

| function | returns | example |
|---|---|---|
| `rnd(key)` | number in (0, 1) | `rnd('uz_UZ:42:0:0:city')` = 0.0345 |
| `rnd_key(locale, seed, batch, pos)` | key of one user | `rnd_key('uz_UZ', 42, 0, 0)` = `uz_UZ:42:0:0` |
| `rnd_int(key, lo, hi)` | integer from lo to hi | `rnd_int('uz_UZ:42:0:0:house', 1, 200)` = 182 |
| `rnd_normal(key, mean, sd)` | normal number | `rnd_normal('uz_UZ:42:0:0:height', 176, 7)` = 174.01 |
| `rnd_lat(key)`, `rnd_lon(key)` | latitude and longitude in degrees | 64.57776, -75.54620 |
| `pick(locale, kind, key)` | random value of one kind | `pick('uz_UZ', 'city', 'uz_UZ:42:0:0:city')` = Samarkand |
| `fill_mask(mask, key)` | mask with every `#` replaced by a digit | `fill_mask('+998 90 ###-##-##', 'uz_UZ:42:0:0:phone')` = +998 90 874-40-81 |
| `sex(key)` | `male` or `female` | `sex('uz_UZ:42:0:0')` = female |
| `first_name(locale, key, sex)` | first name | Iroda |
| `last_name(locale, key, sex)` | last name in the form for this sex | Jalilova |
| `patronymic(locale, key, sex)` | father's name and the locale word | Mengziyo qizi |
| `full_name(locale, key, sex)` | name in one of four formats | Ms. Iroda Jalilova |
| `address(locale, key)` | address in one of three formats | Samarkand, Istiqlol ko'chasi, 182-uy, 9-xonadon |
| `phone(locale, key)` | phone in one of four formats | 8 (701) 307-74-51 |
| `email(locale, key, sex)` | email in one of four formats | iroda.jalilova@icloud.com |
| `height_weight(key, sex)` | `height` in cm and `weight` in kg | 161.2, 52.5 |
| `generate_users(locale, seed, batch, count default 10)` | table of users | see below |

`generate_users` returns `count` rows with the columns `num, name, sex, address, latitude, longitude, height,
weight, eye_color, hair_color, phone, email`, where `num = batch * count + position + 1`. User number
`position` of a batch uses the key `rnd_key(locale, seed, batch, position)`, so it is always the same person.

```sql
select num, name, address, phone, email from generate_users('uz_UZ', 42, 0, 3);
```

```
 1 | Ms. Iroda Jalilova  | Samarkand, Istiqlol ko'chasi, 182-uy, 9-xonadon    | 33 761 28 40  | iroda.jalilova@icloud.com
 2 | Habiba Asadova      | Kattaqo'rg'on, Farg'ona ko'chasi, 183-uy           | 91 101 22 82  | h.asadova48@outlook.com
 3 | Mustafayeva Anbaroy | Asaka, Abdulla Qodiriy ko'chasi, 95-uy, 90-xonadon | +998939848527 | mustafayeva.anbaroy6@icloud.com
```

## Algorithms

**Random number.** `rnd` takes `md5(key)`, 32 hex digits, and keeps the first 13 of them. This is a 52-bit
integer n from 0 to 2^52 - 1, and the result is (n + 0.5) / 2^52. A double holds 52 bits exactly, and the
0.5 keeps the result away from 0 and 1, so `ln(u)` below always works. md5 mixes its input well, so keys that
differ in one character give unrelated numbers. There is no `setseed()` and no state: the result depends only
on the key. `rnd_int` returns lo + floor(u * (hi - lo + 1)), and `pick` returns the value with
`idx = rnd_int(key, 0, n - 1)`. For example `rnd('uz_UZ:42:0:0:city')` = 0.0345, 0.0345 * 40 = 1.38, so the
city is `idx` 1, Samarkand.

**Normal distribution (Box-Muller).** If u1 and u2 are independent and uniform on (0, 1), then
z = sqrt(-2 ln u1) * cos(2 pi u2) has the standard normal distribution N(0, 1). `rnd_normal` takes u1 and u2
from the keys `key:u1` and `key:u2` and returns mean + sd * z.

**Height and weight.** `height_weight` takes two independent N(0, 1) numbers z1 and z2:

```
height = h + hs * z1
weight = w + ws * (0.5 * z1 + sqrt(0.75) * z2)
```

| sex | h, hs (cm) | w, ws (kg) |
|---|---|---|
| male | 176, 7 | 76, 12 |
| female | 163, 6.5 | 62, 10 |

The value in brackets is again N(0, 1), because 0.5^2 + 0.75 = 1, and its correlation with z1 is 0.5. So
taller people are heavier on average, but not always. Both values are rounded to 0.1.

**Coordinates.** The area of the sphere between the equator and latitude φ is proportional to sin φ. For a
uniform point sin φ must be uniform on [-1, 1], so `rnd_lat` returns φ = asin(2u - 1). Longitude is
360v - 180. With latitude 180u - 90 there would be too many points near the poles. Check: half of the sphere
has |φ| < 30°, because sin 30° = 0.5; a uniform latitude would give only 1/3.

**Name.** The sex is 50/50. First and last name come from `first_<sex>` and `last_<sex>`, so a woman gets
Jalilova, not Jalilov. The title comes from `title_<sex>`. The patronymic is a random male first name (the
father) plus `o'g'li` / `qizi` (uz_UZ) or `uly` / `qyzy` (kk_KZ). `full_name` picks one of four formats with
equal chance: `Iroda Jalilova`, `Ms. Iroda Jalilova`, `Jalilova Iroda`, `Jalilova Iroda Mengziyo qizi`.

**Address, phone, email.** The address uses the locale words: `City, Street ko'chasi, 15-uy`,
`Street ko'chasi 15, City` or `City, Street ko'chasi, 15-uy, 23-xonadon`. The phone mask is filled by
`format(mask, country, operator)`, `%1$s` is the country code and `%2$s` the operator code, and then every `#`
becomes a random digit. The email is `first.last`, `last.first` + 1..99, `f.last` + 1..999 or `firstlast` + a
year 1970..2008, in lower case, without characters other than `a-z`, `0-9` and the dot (A'zam becomes azam).

## How many users the data gives

| | uz_UZ | kk_KZ |
|---|---|---|
| first and last name pairs | 157,275 | 759,408 |
| full names, all four formats | 95,623,200 | 2,644,258,656 |
| addresses | 60,800,000 | 60,800,000 |
| phone numbers (operators * 10^7) | 130,000,000 | 80,000,000 |

Pairs are 605 * 135 + 560 * 135 for uz_UZ and 3479 * 156 + 1389 * 156 for kk_KZ. With the patronymic the
number grows 605 and 3479 times. So 100,000 to 1,000,000 users have enough different names. Single names
repeat, as in real life, but a whole user practically never repeats: in a test with 25,000 users per locale
24,981 (uz_UZ) and 24,997 (kk_KZ) emails were different.

## Data sources

- Uzbek first names: [azamroziboyev/uzbek_names](https://github.com/azamroziboyev/uzbek_names), public domain
  according to the repository README.
- Kazakh first names: [KazPER](https://github.com/yeshpanovrustem/KazPER) by Rustem Yeshpanov, CC BY 4.0.
- Uzbek operator codes: [Telephone numbers in Uzbekistan](https://en.wikipedia.org/wiki/Telephone_numbers_in_Uzbekistan).
- Kazakh operator codes: [mimesis](https://github.com/lk-geimfari/mimesis), `datasets/kk/person.json`, MIT.
- Last names, cities, streets, titles, colors and email domains were collected for this study project.
